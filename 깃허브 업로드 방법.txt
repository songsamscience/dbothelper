 송쌤과학 디벗 업무 도우미 — 깃허브(GitHub) 안전 업로드 안내
 최종 정리 : 2026-08-07
====================================================================

이 파일은 사이트를 인터넷에 공개할 때 "무엇을 올리고, 무엇을 올리면
안 되는지"를 정리한 것입니다. 순서대로만 따라 하시면 됩니다.


────────────────────────────────────────────────────────────────────
0. 가장 먼저 — 딱 세 가지만 기억하세요
────────────────────────────────────────────────────────────────────

  (1) 비밀번호는 올리지 않는다
      와이파이 비밀번호, 계정 초기 비밀번호, 관리자 비밀번호는
      절대 파일에 적지 않습니다. "담임 선생님이 안내"처럼 적으세요.

  (2) 학생·교사 개인정보는 올리지 않는다
      학생 이름, 학번, 연락처, 교사 실명이 담긴 파일은 올리지 않습니다.

  (3) 한 번 올라간 것은 지워도 남는다
      깃허브는 기록(커밋 히스토리)이 남습니다. 파일을 지워도 과거
      기록에서 되살릴 수 있으므로, 올리기 전에 확인하는 것이 유일한
      방법입니다.


  ★ 폴더 구조를 이렇게 정리해 두었습니다 ★

      송쌤과학 디벗업무도우미/
      ├── index.html                     ← 올림
      ├── README.md                      ← 올림
      ├── 깃허브 업로드 방법.txt          ← 올림
      ├── assets/                        ← 올림 (폴더째)
      ├── _원본자료 (업로드 제외)/        ← 올리지 않음 ✗
      │     ├── 이미지 소스/
      │     └── 자료 양식/
      ├── 디벗 MDM 매뉴얼/                ← 올리지 않음 ✗ (교육청 원본 — 개인정보가 찍힌 화면 있음)
      ├── 디벗 양품화/                    ← 올리지 않음 ✗ (공문 붙임 원본)
      └── 센스쿨 자료/                    ← 올리지 않음 ✗ (SEN스쿨 · AIEP 매뉴얼 원본)

    ※ 사이트에는 assets/files/ 안에 정리한 사본만 올립니다.
      MDM 매뉴얼은 학생 이름 · 계정 · 연락처가 보이던 화면을 지운 사본,
      양품화 양식은 작성자 이름(메타데이터)을 지운 사본입니다.

  → 규칙은 하나입니다.
    "밑줄( _ )로 시작하는 폴더만 빼고 전부 올린다."


────────────────────────────────────────────────────────────────────
1. 올려도 되는 것 / 올리면 안 되는 것
────────────────────────────────────────────────────────────────────

■ 올려도 되는 것 (지금 폴더에 있는 것들)

    index.html
    README.md
    .gitignore
    깃허브 업로드 방법.txt   ← 이 파일
    assets/css/style.css
    assets/js/app.js
    assets/js/data.js
    assets/img/            (월별 배너, 예시 이미지 등)
    assets/files/          (양식·공문 등 배포용 자료)

■ 올리면 안 되는 것

    · 학생 명단, 반편성 자료, 계정 목록 (CSV, XLSX 등)
    · 학생·교사 이름이 들어간 점검표, 반납확인서 실물
    · 와이파이 비밀번호, 계정 비밀번호가 적힌 문서
    · 학교 내부 결재 문서 원본
    · "_원본자료 (업로드 제외)/" 폴더 전체
      → 원본 이미지와 학교 내부 양식이 들어 있어 용량도 크고
        개인정보가 섞여 있을 수 있습니다.
      → .gitignore 에 이미 등록되어 있어 자동으로 제외됩니다.

■ 지금 .gitignore 에 등록된 제외 대상

    .DS_Store          (맥에서 자동 생성되는 숨김 파일)
    Thumbs.db          (윈도우 미리보기 파일)
    *.tmp
    ~$*                (한글·워드가 만드는 임시 파일)
    .claude/           (편집기 설정)
    _*/                (밑줄로 시작하는 폴더 전부)


────────────────────────────────────────────────────────────────────
2. 올리기 전 최종 점검 (5분)
────────────────────────────────────────────────────────────────────

  □ 1. 사이트에서 [학교 정보] 메뉴를 열고
        · 와이파이 비밀번호 칸이 비어 있거나 "담임 안내"로 되어 있는가?
        · 계정 초기 비밀번호 칸이 실제 비밀번호가 아닌가?
        · 교사 실명 대신 "디벗 담당 교사"처럼 적혀 있는가?

     ※ [학교 정보]에 입력한 값은 브라우저에만 저장되고 파일에는
        저장되지 않습니다. 다만 assets/js/data.js 의 "예시 문구"에
        실제 값을 적어두었다면 그것은 파일에 남으니 확인하세요.

  □ 2. assets/files/ 폴더를 열어
        · 학생 이름이나 학번이 적힌 파일이 없는가?
        · 실제 결재가 끝난 학교 내부 문서가 섞여 있지 않은가?

  □ 3. assets/img/ 폴더를 열어
        · 학생 얼굴이 나온 사진이 없는가?
        · 화면 캡처에 학생 이름·학번이 보이지 않는가?
          (보인다면 모자이크 처리 후 다시 저장)

  □ 4. 폴더 전체 용량이 100MB를 넘지 않는가?
        · 깃허브는 파일 1개당 100MB, 저장소 전체 1GB를 권장합니다.
        · 현재 배포 대상은 약 171MB · 파일 112개이고,
          가장 큰 파일이 12MB라 웹 업로드(파일당 25MB)로도 올라갑니다.
          (2026. 10. MDM 관리자 매뉴얼 8개와 SEN스쿨 · AIEP 매뉴얼 8개를 더하면서 100MB를 넘었습니다.
           깃허브 권장 한도 1GB에는 여유가 있습니다.)
        · 웹으로 올릴 때 한 번에 올릴 수 있는 파일은 100개까지입니다.
          assets 폴더를 통째로 끌어다 놓으면 한 번에 처리됩니다.


────────────────────────────────────────────────────────────────────
3. 올리는 방법 ① — 웹에서 끌어다 놓기 (가장 쉬움, 추천)
────────────────────────────────────────────────────────────────────

  1) https://github.com 에 로그인합니다. (계정이 없으면 가입)

  2) 오른쪽 위 [+] → [New repository] 클릭

  3) 아래처럼 입력합니다.
       Repository name : debut-helper   (영문·숫자·하이픈만)
       Description     : 디벗 업무 도우미
       공개 범위       : Public  (누구나 볼 수 있음)
                        Private (나만 볼 수 있음 — 처음엔 이쪽 추천)
       ※ "Add a README file" 은 체크하지 마세요.

  4) [Create repository] 클릭

  5) 다음 화면에서 "uploading an existing file" 링크를 클릭합니다.

  6) 파일 탐색기(윈도우) 또는 파인더(맥)에서
     이 폴더 안의 아래 항목을 선택해 브라우저 창에 끌어다 놓습니다.

         index.html
         README.md
         깃허브 업로드 방법.txt
         assets  (폴더째로)

     ※ 쉬운 방법 : 폴더 안에서 Ctrl+A (맥은 Cmd+A) 로 전체 선택한 뒤,
       "_원본자료 (업로드 제외)" 폴더만 Ctrl(맥은 Cmd) 누른 채 클릭해
       선택을 풀고 끌어다 놓으면 됩니다.

     ※ index.html 이 저장소 맨 위(root)에 보여야 합니다.
       "송쌤과학 디벗업무도우미/index.html" 처럼 한 겹 더 들어가 있으면
       주소로 접속했을 때 화면이 나오지 않습니다.

  7) 아래 [Commit changes] 를 누르면 업로드가 끝납니다.


────────────────────────────────────────────────────────────────────
4. 올리는 방법 ② — 명령어로 올리기 (한 번 익히면 훨씬 빠름)
────────────────────────────────────────────────────────────────────

  터미널(맥) 또는 Git Bash(윈도우)에서 이 폴더로 이동한 뒤,
  아래를 한 줄씩 실행합니다.

      git init
      git add .
      git status          ← 여기서 반드시 확인!
      git commit -m "디벗 업무 도우미"
      git branch -M main
      git remote add origin https://github.com/사용자명/저장소명.git
      git push -u origin main

  ★ 세 번째 줄 git status 가 가장 중요합니다.
    화면에 나오는 파일 목록에 "_원본자료" 가 보이면 안 됩니다.
    보인다면 .gitignore 를 확인하세요.

  ※ 두 번째 올릴 때부터는 아래 세 줄이면 됩니다.

      git add .
      git commit -m "무엇을 고쳤는지 한 줄로"
      git push


────────────────────────────────────────────────────────────────────
5. 인터넷 주소로 공개하기 (GitHub Pages)
────────────────────────────────────────────────────────────────────

  1) 만든 저장소에서 [Settings] 탭 클릭
  2) 왼쪽 메뉴에서 [Pages] 클릭
  3) Source 를 아래처럼 맞춥니다.
       Source : Deploy from a branch
       Branch : main  /  (root)
  4) [Save] 클릭
  5) 1~2분 뒤 아래 주소로 접속됩니다.

       https://사용자명.github.io/저장소명/

  ※ Private 저장소는 무료 요금제에서 Pages 를 쓸 수 없습니다.
    공개 주소가 필요하면 Public 으로 바꿔야 하는데, 그 전에
    2번 항목의 점검을 반드시 다시 하세요.


────────────────────────────────────────────────────────────────────
6. 실수로 올렸을 때
────────────────────────────────────────────────────────────────────

  개인정보나 비밀번호가 담긴 파일을 올려버렸다면,
  파일만 지우는 것으로는 부족합니다. 아래 순서로 처리하세요.

  1) 급한 대로 저장소를 즉시 Private 으로 바꾸거나 삭제합니다.
       Settings → 맨 아래 Danger Zone → Change visibility / Delete

  2) 노출된 비밀번호는 전부 바꿉니다.
       와이파이 비밀번호, 계정 비밀번호, 관리자 비밀번호

  3) 학생 개인정보가 포함되었다면 학교 개인정보 보호책임자
     (보통 교감 선생님)에게 알리고 학교 규정에 따라 처리합니다.

  4) 저장소를 새로 만들어 처음부터 다시 올리는 것이
     기록을 지우는 것보다 확실하고 빠릅니다.


────────────────────────────────────────────────────────────────────
7. 자주 묻는 것
────────────────────────────────────────────────────────────────────

  Q. 한글 파일 이름을 써도 되나요?
  A. 됩니다. 다만 간혹 브라우저에 따라 문제가 생기므로,
     새로 만드는 파일은 영문·숫자·밑줄(_)로 짓는 편이 안전합니다.
     이미 들어 있는 한글 파일명은 그대로 두어도 동작합니다.

  Q. 파일을 고치면 사이트에 언제 반영되나요?
  A. 다시 올린 뒤 1~2분이면 반영됩니다. 바로 안 보이면
     브라우저에서 Ctrl+F5 (맥은 Cmd+Shift+R) 로 새로고침하세요.

  Q. 내용은 어디를 고쳐야 하나요?
  A. 메뉴와 본문은 전부 assets/js/data.js 한 파일에 있습니다.
     자세한 설명은 README.md 를 보세요.

  Q. 첨부파일을 추가하려면?
  A. assets/files/ 폴더에 파일을 넣고, data.js 의 해당 목록에
     파일 이름을 똑같이 적으면 됩니다. 이미지는 assets/img/ 폴더입니다.

  Q. 다음 담당자에게 어떻게 넘기나요?
  A. 사이트 [학교 정보] 메뉴에서 [설정 내려받기] 를 눌러 나온
     JSON 파일과 저장소 주소를 함께 넘기면 됩니다.
