# 송쌤과학 디벗 업무 도우미

학교 디벗(학생 스마트기기) 담당 교사가 한 해 동안 처리해야 할 업무를
**절차 · 체크리스트 · 서식**으로 정리한 정적 웹사이트입니다.

빌드 도구가 전혀 필요 없습니다. 이 폴더를 GitHub 저장소에 그대로 올리면 바로 동작합니다.

---

## 폴더 구조

```
송쌤과학 디벗업무도우미/
├── index.html                     ← 사이트 뼈대 (건드릴 일 거의 없음)
├── assets/
│   ├── css/style.css              ← 디자인
│   ├── js/data.js                 ← ★ 메뉴와 내용 (여기만 고치면 됩니다)
│   ├── js/app.js                  ← 화면 그리는 로직
│   ├── files/                     ← ★ PDF · 한글 · 엑셀 첨부파일을 넣는 곳
│   └── img/                       ← ★ 사진 · 화면 캡처를 넣는 곳
├── README.md
├── 깃허브 업로드 방법.txt
└── _원본자료 (업로드 제외)/        ← 올리지 않음 ✗
      ├── 이미지 소스/               원본 배너 (용량 큼)
      └── 자료 양식/                 학교 내부 양식 원본 (개인정보 가능)
```

> **업로드 규칙은 하나입니다 — 밑줄(`_`)로 시작하는 폴더만 빼고 전부 올립니다.**
> `.gitignore`에 `_*/`로 등록되어 있어 `git`으로 올릴 때는 자동 제외됩니다.

## 자료 넣는 방법 (base64 사용 안 함)

이미지를 base64로 HTML에 박아 넣으면 파일이 수 MB로 불어납니다.
이 사이트는 **파일을 폴더에 두고 경로만 연결**하는 방식이라 HTML 용량이 커지지 않습니다.

### 1) 첨부파일 (PDF, 한글, 엑셀 …)

1. 파일을 `assets/files/` 폴더에 넣습니다.
2. `assets/js/data.js`에서 해당 메뉴의 `files` 블록을 찾아 이름을 맞춥니다.

```js
{ t:'files', title:'첨부 자료', items:[
  { name:'디벗 반납증', path:'assets/files/디벗_반납증.pdf', desc:'A4 2매 절취선 포함' }
]}
```

아직 파일을 넣지 않았다면 사이트에서 **“준비 중”** 배지로 표시됩니다.

### 2) 이미지

1. 이미지를 `assets/img/` 폴더에 넣습니다.
2. `data.js`의 `gallery` 블록에 경로를 적습니다.

```js
{ t:'gallery', title:'화면 예시', items:[
  { src:'assets/img/rules-poster.png', cap:'디벗 사용 규칙 포스터' }
]}
```

이미지가 없으면 **“이미지를 넣어주세요 + 필요한 경로”** 안내 상자가 대신 표시되므로,
무엇이 빠졌는지 화면만 봐도 알 수 있습니다.

### 파일 이름 규칙

- 공백 대신 `_` (밑줄) 사용 — 예: `디벗_반납증.pdf`
- 한글 파일명도 GitHub Pages에서 정상 동작하지만, 문제가 생기면 영문으로 바꾸세요.
- **대소문자를 구분합니다.** `Poster.png` 와 `poster.png` 는 다른 파일입니다.

## 메뉴 추가하는 방법

`assets/js/data.js`의 `PAGES` 배열에 객체 하나를 추가하면 상단 메뉴와 홈 카드가
자동으로 만들어집니다.

```js
{
  id:'new-menu',              // 주소가 됩니다 → #/new-menu
  no:11,
  em:'🧰',                    // 메뉴 아이콘 (이모지)
  title:'새 업무 이름',
  short:'짧은 메뉴명',         // 상단 메뉴에 표시
  tag:'doc',                  // doc | guide | check | link
  tagTxt:'문서 제작',
  summary:'한 줄 설명',
  blocks:[
    { t:'rich', html:'<p>본문</p>' },
    { t:'checklist', title:'절차', items:[{ txt:'할 일', sub:'설명' }] }
  ]
}
```

### 사용 가능한 블록

| 종류 | 용도 |
|---|---|
| `rich` | 자유 서술 (HTML) |
| `checklist` | 진행률에 반영되는 체크리스트 (브라우저에 저장됨) |
| `notes` | 강조 안내 상자 (`info` / `tip` / `warn` / `bad`) |
| `files` | 첨부파일 내려받기 목록 |
| `gallery` | 이미지 목록 |
| `links` | 외부 사이트 링크 목록 |
| `table` | 표 |
| `months` | 월별 업무 카드 (배너 + 구분 태그 업무표 + 공문 요약) |
| `timeline` | 월별 타임라인 (단순형) |
| `profile` | 학교 기본 정보 입력 폼 (사이트 전체가 공유) |
| `rulegen` | 사용 규칙 포스터 생성기 |
| `wifigen` | 와이파이 접속 안내문 생성기 (공통 / 구역별 선택 · QR · 엑셀 업로드) |
| `cabgen` | 충전함 안내문 생성기 (인쇄물 / ChatGPT · Google Flow 프롬프트) |
| `csgen` | 개인정보 수집·이용 동의서 생성기 (초안 / 삽화 프롬프트) |
| `returngen` | 반납 확인서 생성기 |
| `edugen` | 사용 교육 자료 생성기 |
| `swgen` | 학운위 계획(안)·심의(안)·목록 엑셀 생성기 |

> 첨부파일이 많은 메뉴는 `assets/files/` 아래에 하위 폴더를 만들어 정리했습니다
> (`council/` · `manuals/` · `accounts/` · `mdm/`). `path`에 하위 폴더까지 적으면 됩니다.

### 학교 정보가 자동으로 채워지는 곳

「학교 정보」에 넣은 값은 각 생성기의 같은 이름 칸을 **미리 채웁니다.**

| 자료 | 「학교 정보」에서 가져오는 것 |
|---|---|
| 사용 교육 자료 | **입력한 모든 항목** |
| 반납 확인서 | `school` · `dept` · `parts`(학년별 구성품 → 반납 항목) |
| 와이파이 안내문 | `school` · `dept` · `wifiMode` · `wifiSsid` · `wifiPw` · `wifi` · 문의처 |
| 충전함 안내문 | `school` · `dept` · `storage` · `chargeRule` · 문의처 |
| 개인정보 동의서 · 학운위 자료 | `school` · `dept` · 문의처 |
| 사용 규칙 포스터 | `school` · `dept` |

- 문의처 칸은 `report1` → `tel` → `teacher` → `dept` 순서로 있는 값을 가져옵니다(`pfContact()`).
- 생성기에서 **직접 고친 칸은 고친 값이 우선**입니다(`contactEdited` · `partsEdited` 표시).
  「처음 예시로 되돌리기」를 누르면 표시가 지워지고 다시 「학교 정보」를 따라갑니다.
- 와이파이는 `wifiMode`(공통/구역별) · `wifiSsid` · `wifiPw` · `wifi`(구역별 목록)를
  「학교 정보」와 「와이파이 안내문 생성기」가 **양방향으로 공유**합니다.
  `wifiMode`가 `one`이면 교육 자료도 구역별 목록 대신 `wifiSsid` 한 줄을 씁니다.

> 항목을 새로 추가하면 **어딘가에서 반드시 읽어 쓰세요.** 입력만 받고 쓰지 않는 칸은
> 채워도 자료에 나오지 않아 사용자가 헷갈립니다.

### 학교 기본 정보 (전역 설정)

「학교 정보」 메뉴에서 한 번 입력하면 **모든 생성기가 같은 값을 씁니다.**
저장 위치는 `localStorage`의 `debut.profile` 하나이며, 포스터·반납증에서
학교 이름이나 부서명을 고쳐도 이 전역 값이 함께 바뀝니다.

입력 항목은 `data.js`의 `profile` 블록 `groups`에서 자유롭게 늘리거나 줄일 수 있고,
`k`(키 이름)를 정하면 `app.js`의 `pfGet()`으로 어디서든 꺼내 쓸 수 있습니다.
**설정 내려받기 / 불러오기**(JSON)로 다음 담당자에게 그대로 넘길 수 있습니다.

> 와이파이 비밀번호와 계정 초기 비밀번호는 공개 저장소에 올리지 마세요.
> "담임 선생님이 안내" 같은 문구를 넣고, 실제 값은 인쇄물에만 적는 것을 권합니다.

### 생성기 블록

`rulegen` · `returngen` · `edugen`은 입력 폼과 A4 미리보기를 만들어 주는 블록입니다.
`defaults`에 적은 값이 처음 화면에 채워지고, 사용자가 고친 내용은 브라우저에
자동 저장됩니다(`debut.rulegen` · `debut.returngen` · `debut.edugen`).

- **rulegen** — 출력 방식(PDF / ChatGPT 이미지 / Google Flow 이미지), 용지 방향(A4 세로·가로),
  디자인 분위기 5종, 학생 캐릭터 포함 여부를 고를 수 있습니다.
  PDF는 그 자리에서 포스터가 완성되고, 이미지 방식은 도구에 맞춘 프롬프트가 만들어집니다.
  분위기 팔레트는 `assets/js/app.js`의 `MOODS`에서 색을 바꾸거나 새로 추가할 수 있습니다.
- **returngen** — 학교 이름·부서명만 넣으면 반납 확인서 A4 양식이 완성됩니다.
  1매 / 2매(학교·학생 보관용), 날짜 자동 입력 여부를 고를 수 있습니다.
- **edugen** — 「학교 정보」에 입력한 값으로 사용 교육 자료를 만듭니다.
  **학생용 안내 자료(여러 쪽)** / **한 장 요약 안내문** / **교사용 45분 구성안** 세 가지이며,
  비워 둔 항목은 자료에서 자동으로 빠집니다. 디벗의 의미, 중요 사용 안내, 빌려주면 안 되는
  이유, 수업 유의사항, 디지털 윤리, 단축키 안내는 학교와 무관한 공통 내용이라
  `app.js`의 `EDU_FIX`에 들어 있습니다.

### 내려받는 형식 네 가지

| 형식 | 어떻게 | 언제 쓰나 |
|---|---|---|
| **PDF** | 인쇄 창 → 대상을 “PDF로 저장” | 화면 그대로 인쇄·배부할 때 |
| **워드(.docx)** | 버튼 한 번으로 바로 저장 | 문구를 직접 고쳐 쓸 때 |
| **한글(.hwpx)** | 버튼 한 번으로 바로 저장 | 학교 공문·가정통신문으로 이어 쓸 때 |
| **HTML** | 버튼 한 번으로 바로 저장 | 파일 하나로 보관·전달할 때 |

워드·한글 파일은 `app.js`에서 **외부 라이브러리 없이** 만듭니다. 흐름은 이렇습니다.

```
인쇄용 HTML → htmlToBlocks() → 블록 목록 ┬→ blocksToWml() → .docx
                                        └→ hwpxBlob()    → .hwpx
```

`htmlToBlocks()`가 HTML을 **형식과 무관한 블록 목록**(문단 · 표 · 쪽 나눔)으로 바꾸고,
워드는 WordprocessingML, 한글은 OWPML로 각각 옮긴 뒤 `zipStore()`가 무압축 ZIP으로 묶습니다.
새 문서 형식을 추가할 때 `htmlToBlocks()`의 클래스 분기(`.sec` `.kv` `.li` `.card` `.note` …)에
맞춰 HTML을 만들면 **두 형식이 함께 따라옵니다.** 한쪽만 고치는 일이 없도록 하세요.

- 용지는 **A4**이고, 생성기에서 고른 **세로형/가로형을 두 형식이 함께 따릅니다.**
- 표는 열마다 글자 수를 재서(`colRatios()`) 너비를 나누고, **본문 폭에 정확히 맞춰** 채웁니다.
  용지 방향이 바뀌면 본문 폭도 함께 바뀌므로 표가 넘치거나 모자라지 않습니다.
- 글꼴은 **맑은 고딕**(`W_FONT` · `H_FONT`)으로 고정되어 있어 어디서 열어도 한글이 깨지지 않습니다.
- 한글 파일은 `mimetype`을 **첫 항목**으로 넣어야 열립니다(`hwpxBlob()`의 파일 순서를 바꾸지 마세요).

> 진짜 PDF를 라이브러리로 직접 만들지 않는 이유: 한글 글꼴을 통째로 넣어야 하고(수 MB),
> 레이아웃을 다시 짜야 해서 **브라우저가 인쇄하는 PDF보다 품질이 떨어집니다.**

## GitHub에 올리기

1. GitHub에서 새 저장소를 만듭니다.
2. 이 폴더의 **모든 파일**을 업로드합니다. (`index.html`이 최상위에 있어야 합니다)
3. 저장소 **Settings → Pages → Source: Deploy from a branch → main / (root)** 선택
4. 잠시 후 `https://<사용자명>.github.io/<저장소명>/` 으로 접속됩니다.

명령줄로 올릴 경우:

```bash
git init && git add . && git commit -m "디벗 업무 도우미" && git branch -M main && git remote add origin https://github.com/<사용자명>/<저장소명>.git && git push -u origin main
```

## 참고 사항

- **체크리스트 진행률**과 **생성기에 입력한 내용**은 브라우저(localStorage)에만 저장됩니다.
  기기를 바꾸면 초기화되므로, 완성한 PDF는 파일로 저장해 두세요.
- **첨부파일 “준비 중” 표시**는 웹 서버에서만 확인됩니다. 파일을 더블클릭해 여는
  `file://` 방식에서는 확인이 생략됩니다.
- 각 페이지는 **인쇄(Ctrl+P)** 시 메뉴·푸터가 빠지고 본문만 출력됩니다.
- 사이트에 담긴 절차·서식은 **일반적인 예시**입니다. 실제 적용 전 해당 연도
  교육청 지침 공문과 학교 규정을 반드시 확인하세요.
